# خطة الاختبار — سجل Orax Remote

كل ما هنا مُنفَّذ أو محدد بأمر. النتائج المسجّلة في نهاية الجولة تشير إلى ما تحقّق فعلًا.

## 1. المستويات

| المستوى | الأمر | ماذا يغطي |
|---|---|---|
| مخطط D1 | `npm run test:schema` | تطبيق الـ migration مرتين، القيود، الفهارس، الاستهلاك الذرّي، التنظيف المحدود، غياب أعمدة الوسائط |
| عقود Worker | `npm run test:worker` | 32 اختبارًا في workerd مع D1 معزول وWebCrypto حقيقي |
| صحة العقد | `npm run lint:openapi` | YAML صالح، كل `$ref` يُحلّ، المسارات تطابق الـ Worker |
| الأنواع | `npx tsc --noEmit` | Worker والاختبارات |
| عميل Rust | `cargo test -p orax-registry` | متجه السلسلة، اشتقاق المعرّف، الـ nonce، رفض العناوين |
| عميل Rust ← Worker | `ORAX_REGISTRY_URL=... cargo test -p orax-registry --test live -- --ignored` | رحلة كاملة على شبكة حقيقية (محليًا أو المنشور) |
| دخان حيّ | `node scripts/smoke.mjs https://<worker>` | 14 فحصًا من خارج التطبيق |
| E2E جهازان | يدوي (§5) | المسار الكامل: رمز → اتصال iroh → موافقة → شاشة/إدخال |

## 2. تغطية الأمان

T1 تسجيل ناجح؛ T1b تعارض المعرّف؛ T2 إعادة تسجيل؛ T3 انحراف زمن؛ T4 إعادة nonce؛ T5 جسم 17 KiB؛
T6 JSON تالف؛ T7 استهلاك مزدوج؛ T8 منتهٍ؛ T9 إلغاء خاطئ/صحيح؛ T10 حد المحاولات؛ T11 حقن؛
T12 جهاز مُبطَل؛ T13 حقل بلا تحكم؛ T14 فشل D1؛ T15 سجلات بلا أسرار؛ T16 بت مقلوب؛ T17 جهاز آخر؛
T18 نوع محتوى؛ T19 AAD غير مطابق. (التفاصيل في الخطة §9.2.)

## 3. الاعتمادية والفوضى

| الحقن | التوقع | الحالة |
|---|---|---|
| D1 غير متاح | 503 مع `Retry-After`، لا 500 ولا تسريب | ✅ اختبار `unavailable` غير مباشر عبر الفشل المغلق |
| Worker يعيد 503 | رسالة واضحة + السقوط إلى الدعوة الكاملة | ✅ مُنفَّذ في الواجهة والخلفية؛ ينتظر تجربة يدوية |
| انقطاع في منتصف `POST /v1/signals` | إعادة بنفس nonce → نفس الرمز | ✅ اختبار الإعادوية |
| رمز منتهٍ | 404 | ✅ |
| جلسة قائمة أثناء تعطل السجل | لا تتأثر | ⏳ E2E |
| ساعة منحرفة | 401 | ✅ |

## 4. الأداء

| المقياس | الطريقة | الهدف الأولي |
|---|---|---|
| CPU لكل طلب | `wrangler tail` → cpuTime | P95 ≤ 5 ms (سقف Free 10) |
| P95 لـ resolve/create | سكربت من 3 مناطق | ≤ 150 ms إقليميًا |
| أثر السجل على بدء الجلسة | فصل زمن الرمز عن زمن iroh | ≤ 1 RTT إضافي |
| نبضات/كتابات | مراجعة `rows_written` | لا كتابة دورية |

## 5. E2E على جهازين (قائمة تحقق)

- [ ] جهازان، شبكتان مختلفتان (خلف NAT مختلفين)، إصداران من التطبيق نفسه.
- [ ] المضيف ينشئ رمزًا (سجل حقيقي)؛ المساعد يحلّه ويتصل.
- [ ] الموافقة على المضيف؛ نقل الشاشة والإدخال يعملان.
- [ ] المسار إما مباشر أو relay (يُسجَّل)، مع RTT.
- [ ] إبطال الرمز قبل الاستهلاك يمنع الاتصال.
- [ ] تعطيل السجل ثم إنشاء رمز يفشل بوضوح والواجهة لا تتجمد.
- [ ] إعادة تشغيل المضيف بعد إبطال جهازه ⇒ 403.
- [ ] تسجيل: التاريخ، الإصدارات، مسار الاتصال، أي انحرافات.
